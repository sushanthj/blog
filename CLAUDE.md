# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal blog/portfolio site at www.sush.one, built with Jekyll using the Duet theme. Hosted on GitHub Pages.

## Development Commands

**All local development runs in Docker.** There is no native-Ruby path — don't add
`bundle exec` commands to the Makefile or suggest them in docs. Docker is the only
prerequisite.

```bash
make serve     # dev server, default config
make staging   # _config.yml + config/staging.yml
make prod      # _config.yml + config/production.yml
make build     # one-off jekyll build into _site/
make shell     # shell inside the container
make clean     # remove _site/ and containers
```

The dev server binds to port **4100** (not Jekyll's default 4000, to avoid clashing
with other local Jekyll sites). Override with `make serve PORT=4200`.

The Makefile is the only entrypoint. It exports `PORT`/`RUBY_VERSION` and sets
`JEKYLL_CONFIG` per target; invoking `docker compose` directly silently falls back
to the defaults baked into `docker/docker-compose.yaml`.

CI is the exception: `.github/workflows/pages.yml` uses native Ruby via
`ruby/setup-ruby` and never touches the Makefile or Docker.

**Drafts**: a post with `published: false` in its front matter is excluded from the
built site. `serve`/`staging` pass `--unpublished` so drafts are visible locally;
`prod` and CI deliberately don't. This hides the page only — assets under `images/`
are still copied to the site.

## Architecture

- **Jekyll site** using `github-pages` gem (not standalone Jekyll)
- **Three collections**: `_posts/`, `_pages/`, and projects (configured in `_config.yml`)
- Posts and pages are organized into subdirectories by category (art, food, projects, blog, work)
- **Config layering**: `_config.yml` (base) + `config/production.yml` or `config/staging.yml` for environment overrides
- **Theme settings**: `_data/settings.yml` controls colors, fonts, navigation, social links, contact form
- **Custom plugin**: `_plugins/image_path_filter.rb`
- **Ruby version**: pinned once in `.ruby-version`; read by CI and passed to the `Dockerfile` as the `RUBY_VERSION` build arg
- **Docker**: `docker/` holds the `Dockerfile` and compose file; build context is the repo root. `network_mode: host` is Linux-only — see the comment in the compose file for the macOS/Windows form
- **Root files are load-bearing**: `CNAME`, `_config.yml`, `index.md`, `404.html`, `Makefile`, `README.md`, `Gemfile*`, `.ruby-version` must stay at the root — don't tidy them into folders
- **CI/deploy**: `.github/workflows/pages.yml` builds with `jekyll build` on every push (no
  Docker involved) — staging config on branches, production config on `main`, which then
  deploys to GitHub Pages via `actions/deploy-pages` (Pages source must be "GitHub Actions")
- **Layouts**: `_layouts/` (default, page, post) with partials in `_includes/`
- **Diagrams**: flowcharts in posts are authored as ` ```mermaid ` fences, rendered
  client-side by `_includes/mermaid.html` (kb-dark themed) and re-rendered after AJAX
  navigation via the `renderMermaid()` hook in `js/duet.js`/`duet-min.js` — don't
  hand-author new flowchart SVGs. Non-flowchart illustrations (curves, grids,
  histograms) stay as SVGs under `images/`. Validate new diagrams with the
  `minlag/mermaid-cli` Docker image (mount a `chmod 777` dir). Note: `linkStyle`
  with comma-separated indices fails to parse — one index per line.
  Full style guide + workflow: `.claude/skills/blog-illustrations/SKILL.md`; the
  illustration SVGs are generated by scripts in `_scripts/illustrations/` — edit
  the generator and re-run it, never the SVG output.
- **Styles**: `_sass/` compiled via Jekyll's asset pipeline
